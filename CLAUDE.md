# Yoshlar Radar — контекст проекта

Хакатон-прототип внутреннего дашборда для хокимията Мирзо-Улугбекского района
(Ташкент): мониторинг занятости молодёжи по 12 махаллям. Весь UI на русском,
все данные синтетические и генерируются на клиенте.

## Читай первым: если задача звучит как «покрась карту в разные цвета»

Категориальная раскраска **уже написана и работает**, и с 14.08.2026 она стоит
по умолчанию: карта при открытии показывает 12 разных цветов, соседние зоны
заведомо различимы. Не строй раскраску заново.

Если пользователь всё равно видит красно-оранжевую карту — он либо переключил
`ToggleGroup` на «По статусу NEET», либо смотрит на мёртвый порт. Проверь порт
первым делом: такая путаница уже была.

## Стек и запуск

React 19 + TypeScript + Vite 8 + TanStack Start/Router + Tailwind v4 + shadcn/ui
+ react-leaflet 5. Приложение живёт в подкаталоге `front/`, репозиторий — в корне.

```bash
cd front
npm install
npm run dev      # http://localhost:8080 — порт задан в vite.config.ts
npm run build
npx tsc --noEmit
```

**Всегда проверяй на `localhost:8080`.** Если Vite скажет «Port 8080 is in use»
и уедет на 8081 — значит сервер уже поднят, не поднимай второй: у пользователя
уже была путаница, когда он смотрел на мёртвый 8081 и решил, что правки не
применились.

**Никогда не делай `pkill -f "vite dev"`** — под маску попадает dev-сервер
пользователя. Свои фоновые процессы убивай по конкретному PID.

## Бэкенд (`back/`)

Спека и пошаговые сессии — в `backend.md` (единственный источник правды по API).
Бэкенд в отдельном каталоге `back/`, фронт в этих сессиях не трогаем. Стек:
Node 22 + TypeScript (ESM) + Fastify 5 + Drizzle ORM + PostgreSQL 16, тесты —
vitest через `app.inject()` против реального Postgres. Порты: API `3001`,
dev-Postgres `5438` (не пересекается с фронтом на `8080`).

Готово (S1): каркас, схема БД (3 таблицы `mahallas`/`people`/`history_events`
на text+CHECK, миграция `back/drizzle/0000_*.sql` с `pg_trgm` и partial/GIN
индексами), `GET /health`, CI `.github/workflows/backend-ci.yml`.

Готово (S2): auth на `@fastify/jwt` (HS256, TTL 12ч; `src/plugins/auth.ts` +
`authenticate` preHandler), `resolveScope` (`src/lib/scope.ts`),
`POST/GET /api/auth/login|me`, `GET /api/meta/mahallas|dictionaries`,
константы-порт из фронта (`src/db/constants.ts`), детерминированный сидер v2
(`generatePeople` порт, `mulberry32(20260814)`; флаги `--count/--anchor/--append/
--lightHistory`, батчи по 1000).

Готово (S3): реестр — `GET /api/people` (пп.6) с фильтрами, поиском, пагинацией,
сортировкой русской коллацией; `GET /api/people/:id` (п.7) с полным профилем и
историей. Динамический WHERE через drizzle `and()`; два запроса (SELECT +
COUNT); whitelist-сортировка (никогда не интерполировать); скоуп (mahalla-роль
видит только свою, district видит всех). Сериализаторы `toPerson()`/
`toPersonListItem()` с JOIN на `mahallas.name`.

Запуск из `back/`:

```bash
cd back && npm install
docker compose up -d          # postgres:16-alpine на :5438
npm run migrate
npm run seed -- --count 250   # людей 250 + история; --anchor для воспроизводимых дат
npm run dev                   # http://localhost:3001 ; /health → {"status":"ok","db":"ok"}
npm run typecheck && npm test
```

Git по бэкенду: ветка `back/s<N>-<slug>` → PR → мерж только после зелёного CI
(`gh pr checks --watch`, затем `gh pr merge --squash --delete-branch`, без
`--auto`). Коммить только `back/ .github/ backend.md CLAUDE.md` — в дереве есть
несвязанные правки фронта, `git add -A` не делать.

## Карта района (`/map`) — главное

### Слои по зуму

`DistrictMap.tsx` → `MapLayers` переключает слой по текущему зуму:

| Зум | Слой |
|-----|------|
| < 9 | `RegionsLayer` — 14 областей Узбекистана |
| 9–12 | `DistrictsLayer` — 10 районов Ташкента |
| ≥ 13 | `MahallaZones` — 12 территорий махаллей |

**Зоны махаллей видны только на зуме 13+.** При открытии страницы `MapBridge`
через 500 мс запускает `flyTo(DISTRICT_CENTER, DISTRICT_ZOOM)` и карта сама
долетает до нужного масштаба. Если видишь контуры областей/районов — это не
поломка, а просто мелкий масштаб; кнопка «Вернуться к району» справа сверху.

### Как построены территории

Официальных границ махаллей в открытых geo-датасетах нет. Территории строятся
в `src/lib/mahallaVoronoi.ts` как диаграмма Вороного от координат-центров
махаллей, обрезанная по контуру района (`d3-delaunay` + `@turf/turf`).
Проверено: сумма площадей 12 зон точно равна площади района (coverage 1.0000),
без нахлёстов и выходов за границу.

**Важная особенность данных.** Координаты в `MAHALLA_COORDS` (`src/lib/data.ts`)
синтетические и заданы по реальному городу, а контур района берётся из
geoBoundaries (ADM2) и смещён примерно на 0.03° к юго-западу. Из-за этого
только 3 точки из 12 попадают внутрь полигона. Прямая обрезка Вороного дала бы
9 пустых зон. Поэтому `fitSeedsToDistrict()` аффинно вписывает облако точек в
bbox района и притягивает внутрь те, что попали в вогнутости. Взаимное
расположение махаллей сохраняется. Сами данные не трогались — вся компенсация
изолирована в одной функции, её легко выкинуть, если появятся настоящие
координаты.

Ещё в файле есть 2 шага релаксации Ллойда: без них разброс площадей был
1.07–5.17 км², с ними 1.2–4.3 км².

`DISTRICT_CENTER` в `src/lib/map-geo.ts` — центр bbox полигона района
(`[41.3015, 69.3145]`), подобран так, чтобы все зоны помещались в кадр.
Старое значение лежало выше северной границы, и половина зон уходила за экран.

Зона «Дархан» разрезана на два куска — это реальная вогнутость границы района,
а не баг отрисовки. `positions` отдаётся в формате Leaflet `LatLng[][][]`
(мультиполигон), иначе второй кусок отрисовался бы дыркой.

### Раскраска — тут два режима, оба уже сделаны

`src/lib/mahalla-colors.ts` + переключатель `ToggleGroup` на `/map` над картой
справа. Режим хранится в `useState` на странице, дефолт — `"mahalla"`.

- **«По махаллям»** (дефолт) — категориальная палитра `MAHALLA_COLORS`,
  12 насыщенных цветов, `fillOpacity` 0.45, на hover 0.65, контур — тот же цвет
  через `darken()`. Легенда — сетка из 12 махаллей.
- **«По статусу NEET»** — emerald / amber / red по доле NEET, `fillOpacity`
  0.35, на hover 0.55. Легенда — три статусных порога.

Цвет закреплён за махаллёй (а не за позицией в переданном списке) — чтобы
инспектор махалли видел тот же цвет, что и в общем виде района.

Вся развилка собрана в одной функции `zoneStyle(stat, mode)` в
`DistrictMap.tsx` — новые режимы добавлять туда.

### Как цвета разводятся между соседями

Раньше цвет брался по индексу махаллы в списке, а порядок списка с географией
не связан — соседние зоны получали близкие оттенки (teal/emerald, pink/red).
Сейчас палитра раздаётся по графу смежности:

- `mahallaNeighbors()` в `mahallaVoronoi.ts` отдаёт соседей каждой зоны — это
  рёбра триангуляции Делоне по тем же центрам, что и у Вороного (считается по
  тем же релаксированным центрам, что и геометрия, через `relaxedSeeds()`).
- `assignPalette()` в `mahalla-colors.ts` жадно раздаёт цвета: сначала зоны
  с наибольшим числом соседей, каждой — самый далёкий (по «redmean») из ещё
  свободных цветов. Каждый цвет уходит ровно одной махалле, поэтому в легенде
  оттенки не повторяются; обычная раскраска графа обошлась бы 4–5 цветами и
  для легенды не годится.
- Раскладка считается один раз лениво и кэшируется в модуле.

Раскладка зависит только от констант (`MAHALLA_COORDS` + контур района), так
что она детерминирована, но при правке координат цвета могут перетасоваться.

### Что менять НЕ надо

Логика Вороного и обрезки turf, попапы по клику (мини-карточка со статами +
кнопка «Открыть махаллю» → `/registry?mahalla=…`), подписи-тултипы в центре
зон. Подписи висят на отдельном некликабельном `Marker` с пустой `divIcon`
(`interactive={false} keyboard={false}`), потому что штатный тултип полигона
Leaflet ставит в геометрический центр, который у вогнутых зон попадает наружу.

## Состояние линта и типов (было таким ДО правок по карте)

- `npx tsc --noEmit` даёт 2 ошибки: `DistrictMap.tsx` (`getElement()?.style`)
  и `vite.config.ts` (`noImplicitReturns`). Обе в коде, который правки по карте
  не трогали.
- `npm run lint` даёт ~785 ошибок форматирования по всему репозиторию: в
  проекте нет `.prettierrc`, поэтому prettier требует `printWidth: 80`, а весь
  код написан под ~100. Одна строка конфига сделает линт зелёным — с
  пользователем не согласовано.

Новый код форматируй под окружающий стиль (~100 символов), а не под дефолт
prettier.

## Как проверять карту в браузере

Расширение Claude in Chrome в этой среде не подключено. Проверка делается через
headless Chrome по CDP — рабочий рецепт:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-first-run \
  --remote-debugging-port=9222 --user-data-dir=/tmp/cdp about:blank &
```

Дальше скриптом на Node (глобальный `WebSocket` есть в Node 22) подключиться к
`http://127.0.0.1:9222/json/version`, создать таргет, и через `Runtime.evaluate`
дёргать DOM. Вход минуется установкой сессии:

```js
localStorage.setItem("yr-session", JSON.stringify({ role: "district", mahalla: null }));
```

Полезные проверки:

```js
document.querySelectorAll("path.mahalla-zone").length        // должно быть 12
document.querySelectorAll(".mahalla-zone-label").length      // должно быть 12
[...document.querySelectorAll("path.mahalla-zone")]
  .map(p => p.getAttribute("fill"))                          // цвета зон
```

Скриншот — `Page.captureScreenshot`. Учти: `flyTo` в headless иногда не
доезжает, и запрос сразу после загрузки вернёт 0 зон — надо дождаться зума 13
или кликнуть «Вернуться к району» и повторить. Пустые белые прямоугольники
вместо подписей на скриншоте при `deviceScaleFactor: 2` — артефакт headless,
а не баг: DOM в этот момент содержит правильный текст.
